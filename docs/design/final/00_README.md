# Tá em Cartaz — Visual Implementation Package v1.0 FINAL

**Status:** FINAL visual/UX implementation baseline  
**Date:** 2026-08-15  
**Audience:** Antigravity / Codex / frontend implementation agents  
**Purpose:** Consolidate all approved visual direction, UX reviews, dynamic-content rules, responsive behavior and anti-invention guardrails into one implementation authority.

## Authority order

When sources disagree, use this order:

1. `Desafio-Elite-Dev-2026.pdf` — external requirements.
2. Latest approved Project / Domain Specification — product/domain/API authority.
3. Current Story / Acceptance Criteria — implementation scope for the current task.
4. `01_VISUAL_UX_SPEC_FINAL.md` — visual/UX implementation authority.
5. `02_REFERENCE_MANIFEST.md` — how to interpret the approved mockups.
6. Historical UX drafts, exploratory mockups and conversations — rationale only.

**A visual mockup can reveal a UX problem; it cannot create domain truth.**

## Files

- `01_VISUAL_UX_SPEC_FINAL.md` — normative final spec.
- `02_REFERENCE_MANIFEST.md` — exact use/ignore instructions for each visual reference.
- `03_ANTIGRAVITY_EXECUTION_BRIEF.md` — implementation protocol for the coding agent.
- `04_VISUAL_ACCEPTANCE_CHECKLIST.md` — review gate before a screen is accepted.
- `references/` — curated visual references. Their content/data is not literal unless the spec says so.

## Supersession rule

For frontend visual/UX implementation, this package **supersedes the older frontend-spec v1.1 where wording conflicts**. The older pack remains useful as decision history. It does **not** supersede Project/Domain/API authority.

## Stop rule

If implementation requires a new decision about product, domain, API, authentication, payment, persistence, ticket credentials or backend behavior:

**STOP. Do not invent. Report the ambiguity, alternatives, trade-offs and affected files.**
